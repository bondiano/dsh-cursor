# Cursor provider

Добавляет Cursor как LLM-провайдера DeepSeek Harness: модели Cursor появляются в общем пикере композера, а настройки — в **Settings → Cursor**.

## Вход

1. Откройте **Settings → Cursor**.
2. Нажмите **Войти через Cursor** и завершите вход в браузере.
3. DSH сохраняет полученный Cursor user API key в credential-записи `dsh-cursor/default`; ключ не показывается повторно и не попадает в конфигурацию.

Если аккаунт уже имеет Cursor API key, его можно сохранить вручную в разделе **Использовать готовый API-ключ**. Для headless-профилей работает `CURSOR_API_KEY`.

## Модели

**Обновить каталог** читает модели аккаунта через официальный Cursor SDK. Для каждой модели можно:

- включить или выключить её в пикере;
- задать отображаемое имя;
- задать бюджет контекста (`500K`, `1M`, …) — плагин выбирает минимальный объявленный тир, который его покрывает; пустое значение оставляет значение модели по умолчанию;
- включить **Fast**, если модель объявляет переключаемый fast-параметр;
- разрешить изображения, если модель их принимает.

Сохранение пишется атомарно в `~/.dsh/plugins/cursor/settings.json` (0600). Пустой список скрывает провайдера из пикера.

## Инструменты и сессии

DSH остаётся владельцем инструментов: Cursor SDK работает без встроенных файловых/shell-инструментов, а каждый tool-call приходит в DSH как обычный вызов, проходит аппрув и исполняется штатным путём. Результат возвращается в тот же SDK-run через одноразовый continuation.

- Отмена, таймаут и неизвестный терминальный статус уничтожают агент; повторной отправки платного запроса нет.
- Временный рабочий каталог удаляется при освобождении агента.
- История DSH передаётся SDK как данные разговора; Cursor сохраняет свой встроенный системный промпт и серверные правила аккаунта.
- temperature/maxTokens/stop не поддерживаются и отклоняются до запроса.
- Новый процесс или изменённая история начинает разговор заново; continuation не переживает рестарт.

## Квоты

Карточка **Расход подписки** и пилюля в композере читают `GetCurrentPeriodUsage` по токену локального Cursor CLI:

- `CURSOR_AUTH_TOKEN`;
- `~/.cursor/auth.json` (macOS), XDG-путь (Linux), `%APPDATA%\Cursor\auth.json` (Windows);
- macOS Keychain — только по явной кнопке, с возможным запросом доступа.

Показываются окна **Total / Auto / API** и время сброса. Без локальной авторизации CLI карточка объясняет, что нужно выполнить `agent login`; на модели это не влияет. Токен CLI никогда не возвращается в браузер.

## Ограничения

- Это интеграция Cursor SDK agent runtime, а не прямой доступ к «чистой» модели: системный промпт Cursor и ограничения аккаунта действуют.
- Мультиаккаунт и пул аккаунтов не входят в эту версию.
- Ключ, созданный при входе, имеет срок действия (по умолчанию 90 дней); после истечения нужно войти снова. Отзыв ключа делается в Cursor Dashboard.
- Если другой плагин уже зарегистрировал маршрут `cursor` (например, `dsh-cursor-provider`), регистрация завершится диагностикой, а не перезапишет чужой адаптер.
- `@cursor/sdk` распространяется по условиям Cursor; плагин использует его как npm-зависимость и не перепубликует.
